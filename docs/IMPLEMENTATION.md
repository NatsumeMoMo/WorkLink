# WorkLink 实现约定

目标平台：Windows 11 x64。

## 网络和身份

- 默认本机服务监听 `127.0.0.1:41443`，frp 使用 TCP 透传映射至该端口。公网映射端口可以自由选择。
- B 配置 A 的公网入口，主动建立一条双向连接。B 可以关闭网络监听。
- 自定义业务协议运行在 TLS 1.3 双向认证连接内，逻辑通道由 yamux 提供。
- 设备证书通过线下邀请文件交换，并核对 SHA-256 指纹；邀请只含公钥材料。
- TLS 必须校验受信任设备证书和设备名，不提供跳过验证选项。
- 私钥使用 Windows DPAPI 机器范围保护，并配合目录 ACL 限制访问。
- 一条连接内可同时发起两个方向的 SSH、文件和任务请求。
- 首次配对默认只允许 SSH 转发；原生文件、命令和 SYSTEM 执行分别授权。

## Windows 和执行

- 同一个 EXE 支持后台服务、前台 daemon、GUI、托盘和 CLI。
- 默认数据目录 `%ProgramData%\WorkLink`，测试可显式指定其他目录。
- CLI/GUI 通过有 ACL 的本地命名管道访问后台；管道拒绝远程客户端。
- SSH 目标固定为本机回环地址，默认 `127.0.0.1:22`。
- 原生普通用户执行必须使用配置所有者的用户令牌；无令牌时返回错误。
- SYSTEM 执行必须同时满足请求显式指定及该设备被授予相应权限。
- SSH 认证失败不自动切换原生兜底。
- 原生任务先持久化任务 ID，再执行；重启后将未完成任务标记为 interrupted，不自动重跑。
- 任务进程放入 Job Object，超时、取消或后台退出时终止进程树。

## 恢复边界

- 自动重连恢复设备通道，不能恢复已断开的 SSH TCP 会话。
- 持久任务独立于传输会话；结果可按任务 ID 查询。
- 文件以临时文件接收，校验完整 SHA-256 后再提交；覆盖必须显式允许。
- 队列、并发、任务输出及历史记录设定上限。

## 开发验证

通过两个独立数据目录在回环地址运行两个真实 daemon，验证双向 TLS、SSH 字节流、权限拒绝、文件续传、任务幂等、断线重连和撤销信任。验证不得修改机器现有 SSH/frp/防火墙配置。
