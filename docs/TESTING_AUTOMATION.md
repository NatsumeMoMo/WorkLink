验证日期：2026-11-17。测试在两台实际 Windows 11 PC，以及 GitHub Windows runner 上执行。个人设备地址、用户名、截图与原始日志只存放在本地忽略目录 `test-artifacts/automation-20261117`。

## 本机验证

- `cargo fmt --check`、`cargo clippy --all-targets --locked -- -D warnings` 通过。
- `cargo test --locked -- --nocapture`：4 个单元测试、2 个端到端测试通过。覆盖旧配置默认权限、Unicode 结果分页/搜索/过期/设备隔离、TLS 双向认证、双向 SSH、SFTP 校验/续传、原生任务去重/取消/重启、自动化双向路由与授权撤回。
- 发布 EXE 使用真实 Edge 与独立临时 profile 完成 10 组自动化检查：启动、512 字符预算分页、控件引用、输入/点击、草稿保护、流式回答完成检测、UUID 去重/冲突、长文本与截图、任务取消/恢复、MCP、真实 WinForms UIA 操作。
- GUI 启动、中文字体、新增自动化入口和截图检查通过。

可复现命令：

```powershell

```

## 两机实测

两端服务均更新至 v0.2.0，使用已有 frp TCP 41443 链路；B 保持只主动连接。两端显式允许 browser/desktop，测试用 SYSTEM 授权结束后恢复为关闭。

| 场景 | 实际结果 |
|---|---|
| B 操作 A 浏览器，加载只有 A 回环地址可访问的页面 | 通过，证明网页访问发生在 A |
| A 的流式网页回答返回 B | 通过，相同 UUID 重试只有一次提交 |
| A 操作 B 浏览器，加载 B 的回环测试页面 | 通过，沿用 B 发起的连接 |
| 长正文 | 32400 字符只返回 1000 字符预览，其余按 offset 读取 |
| 小预算控件快照 | 1800 字符预算返回约 1288 字符结果 |
| 浏览器截图 | 约 93 KB JPEG，下载 SHA-256 一致，普通结果无图片 Base64 |
| 两方向桌面自动化 | 两端自建 WinForms 窗口均完成枚举、快照、填入、点击、截图和下载 |
| 执行中撤回 browser 授权 | 在运行任务停止，恢复授权后可查询 cancelled |
| 通道强制断开约 11 秒 | A 继续完成网页回答，恢复连接按原 ID 查询成功，重复 ID 未再次发送 |
| SSH 回归 | 自动化测试后原 SSH 命令仍成功 |

公网测试发现并修正了仅在服务启动环境出现的问题：headless 助手原先被强制放入 Session 0，Edge 能启动但页面渲染超时。保留所有者会话与桌面后，两方向的真实浏览器检查通过。没有关闭浏览器沙箱来绕过问题。

进程检查还发现旧原生任务在后台被强制终止时，可能在创建进程与绑定 Job Object 之间遗留挂起进程。改为通过 Windows 进程属性在创建时原子绑定 Job，并增加后台崩溃后不存在 PowerShell 子进程的断言。

## 验证边界

网页提问使用自建的延迟、流式聊天页面验证。真实 ChatGPT 页面已在 A 的专用浏览器中打开并读取控件，测试时显示未登录；未把它视为已验证 GPT Pro 账户或所有模型状态。

未进行重启整机、注销用户或冷启动无人登录的浏览器测试。桌面自动化的前提是配置所有者已登录且解锁；headless 模式仍依赖现存的用户登录令牌。任意应用的 UIA 实现、验证码、跨域 iframe、UAC 安全桌面等不在本次通过范围内。

这些结果说明所列场景已实测通过，不等于对所有网络和第三方网页变化作稳定性保证。
